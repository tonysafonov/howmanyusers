# Pre-scan: gramkit backend (FastAPI + SQLAlchemy)

**Repo:** [tonysafonov/gramkit](https://github.com/tonysafonov/gramkit) at
[`f276446`](https://github.com/tonysafonov/gramkit/tree/f276446f21ee866d5a849dbce62d8ea0541d7c48) (2026-11-08):
`core/backend/src/core` and the two templates (`apps/template-vue`, `apps/template-react`, whose backends are the same).
**Method:** `references/prescan.md`: read the code only. No servers, no load. Every row below is a **hypothesis**
until a probe confirms it.

## Context: what is already fixed

gramkit has already been through a profiling fix ladder on a rented rig (README
[Performance](https://github.com/tonysafonov/gramkit/blob/f276446f21ee866d5a849dbce62d8ea0541d7c48/README.md#L176-L203),
[CHANGELOG](https://github.com/tonysafonov/gramkit/blob/f276446f21ee866d5a849dbce62d8ea0541d7c48/CHANGELOG.md)): one Bot
and one arq pool per process, a bounded DB pool, pure-ASGI middleware, real dependencies instead of
`dependency_overrides`, log writes off the loop, and auth answering 503 on infrastructure errors. That took its Conduit
bench from 220 to 1,300 users on 2 vCPU. So this pre-scan is about **what is left**, mostly paths the Conduit bench
never exercised: logged-out visitors, payments, email login, and what changes when you run more than one worker.

**Hot path walked:** the app open (`POST /process_start`, fired on mount by
[useAppInit.ts:161](https://github.com/tonysafonov/gramkit/blob/f276446f21ee866d5a849dbce62d8ea0541d7c48/apps/template-vue/frontend/src/app/composables/useAppInit.ts#L161)),
`GET /users/me`, what every request pays before the handler (middleware → `get_user` → `get_services` → `get_repo`),
the three ways a caller is identified (initData, session cookie, shared guest), payments, email auth, process setup.

## What to measure first

The measurement decides the order, not this table (`references/fixes.md`). On a stand, these probes split the work:
1. A logged-out journey at a few opens per second confirms or kills #4 and #5 in one run.
2. A hold with YooKassa and Resend stubbed at a fixed delay settles #1 and #2.
3. `cpuprobe.sh` on `GET /users/me` with and without pre-ping (#8) and the slimmer `get_services` (#9).
4. Then raise the worker count (#6) with the pool fixed first (#7).
